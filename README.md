# Claude Proxy

用于桌面代理配置的 Codex 技能：从已有节点或一台尚未搭建节点的 VPS 出发，衔接节点搭建、客户端导入、国内外分流、TUN、DNS、断网防护、备份、自动恢复和分阶段验收。

**密码由你在本机终端输入，需要管理员权限的命令由你亲自运行。** AI 负责体检、生成配置和脚本、读取日志并逐项核验，不需要你编写 YAML。

本项目是配置工作流和部署工具，不提供 VPS、节点订阅或账号服务；不保证第三方服务的账号、登录或地区可用性。

## 支持范围

| 场景 | 当前支持情况 |
| --- | --- |
| 桌面完整自动部署 | macOS + Clash Verge Rev **2.5.10**，稳定版 Mihomo 核心 |
| 裸 VPS 自动搭建 | Debian/Ubuntu，systemd 247+，Python 3.9+，x86_64/aarch64，公网 IPv4 |
| 新建节点协议 | Xray Shadowsocks 2022，TCP；不需要域名或证书，海外 UDP 明确拒绝 |
| 裸 VPS 自动搭建后导入 | A 模式：VPS 直接作为海外出口 |
| 已有节点与住宅代理 | 支持选择已有节点；B 模式可配置住宅 SOCKS5 经跳板，需单独提供并验证住宅出口 |
| 其他版本或桌面客户端 | 先识别并报告支持范围，不自动套用现有适配器 |
| 已有 TUN/同名断网防护 | 从审计、诊断、修复开始，不使用首次安装器覆盖 |

本机还需能运行 `/usr/bin/python3`（3.9+）、macOS Ruby 和 OpenSSH。首次安装客户端及缺失的系统开发工具需按提示处理，不会被静默安装。服务端遇到不能安全识别的防火墙规则会停止并报告。

## 安装技能

将整个仓库放入你的 Codex 技能目录，文件夹名保持 `claude-proxy`。默认目录为 `~/.codex/skills/`；如果自定义了 `CODEX_HOME`，使用对应目录下的 `skills/`。

在仓库页面点击 **Code → HTTPS** 复制克隆地址，替换下面的占位文本后运行：

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone "<本仓库的克隆地址>" "${CODEX_HOME:-$HOME/.codex}/skills/claude-proxy"
```

已有同名目录时，先检查版本并备份，不直接覆盖。也可以通过仓库的 **Code → Download ZIP** 下载，解压后将包含 `SKILL.md` 的文件夹命名为 `claude-proxy`，放到上述目录。

安装后在新会话中使用 `$claude-proxy`。如果技能列表尚未出现，重新打开 Codex 后再试。

## 开始使用

### 我只有 VPS，还没有节点

将下面这段发给 Codex，并填写自己的连接信息：

```text
使用 $claude-proxy。

我只有一台 VPS，还没有搭建代理节点。
请先检查本机客户端与服务器环境，再准备节点搭建、自动导入、分流、TUN、DNS 和断网防护。

VPS 公网 IP：填写你的 IP
SSH 端口：填写实际端口
登录用户名：填写实际用户名
登录方式：密码或本机 SSH 密钥

密码由我在本机终端输入，管理员命令由我亲自运行。
先说明具体改动和退出代理后的网络行为，得到确认再部署。
完成备份和离线恢复准备，每个阶段结束先读日志，再继续下一阶段。
```

不要把 SSH 密码、私钥内容、订阅令牌或住宅代理密码贴到聊天里。首次 SSH 连接时，需要你与厂商面板核对主机指纹。

### 我已经有可用节点

先在客户端导入并选中真实订阅或节点，然后发送：

```text
使用 $claude-proxy。

我已有可用节点，请先只读检查客户端、节点、DNS、路由与其他代理或 VPN。
把电脑配置成国内直连，其余通过手动选择的海外出口；海外出口中不包含 DIRECT，不自动回退直连。
准备 TUN、DNS、自启、断网防护、完整备份、失败恢复和逐项验收。
管理员命令由我自己运行。先列出可用节点和具体改动，确认后再部署。
```

已有节点会跳过 VPS 搭建阶段。节点地区按实际出口核验，不凭节点名称判断。

国内验收目标由你提供：2～4 个不同主机的普通网页地址、1 个能返回纯 IP 或 JSON IP 字段的测 IP 接口。AI 根据只读证据核实本地公网 IPv4 及地区，填入私有 `domestic_tests` 选项。包内不含默认国内域名或参考网址，未提供目标时会停止部署准备；不会直接算验收通过，也不会为测试通过自动加白。

## 完整流程与需要你操作的地方

| 阶段 | AI 和脚本完成什么 | 你需要做什么 |
| --- | --- | --- |
| 1. 本机体检 | 识别客户端、版本、核心、端口、系统代理、DNS、路由、服务和冲突 | 提供使用目标；先安装并打开一次受支持客户端 |
| 2. VPS 体检 | 生成 SSH 入口，检查系统、端口、服务、防火墙和官方发布信息 | 运行 `connect-and-inspect.sh`，本机输入密码、核对主机指纹 |
| 3. 确认方案 | 说明协议、端口、出口、修改范围、恢复方式和开关行为 | 确认方案，选择退出代理后的网络行为 |
| 4. 搭建节点 | 备份、校验官方二进制、部署独立服务、测试真实出口，失败恢复 | 运行 `deploy-node.sh`；如云安全组阻断端口，在厂商面板开放所选 TCP 端口 |
| 5. 桌面准备 | 再测节点，备份配置，生成新本地配置与全局覆写、离线恢复及急救文件 | 保存桌面的“断网急救.txt”，建议用手机拍照 |
| 6. 桌面部署 | 退出客户端、导入节点、配置服务/TUN/DNS/自启、重开，验收 1～6 | 运行本批次的 `sudo sh "实际路径/apply.sh"` |
| 7. 安装防护 | 仅在 TUN 和前阶段通过后安装 PF/守护，验收 7～8 | 运行 `sudo sh "实际路径/install-guard.sh"` |
| 8. 故障演练 | 坏节点、TUN 故障、客户端退出，每项结束自动恢复，验收 9～11 | 运行 `sudo sh "实际路径/drill.sh"` |
| 9. 交付 | 汇总结果、当前状态、日志、两端恢复命令及日常操作方式 | 核对实际使用体验，按需补测重启或浏览器场景 |

**每个入口由 AI 给出本机真实路径。按阶段执行，AI 读取日志后再继续；不要把表格中的占位路径直接复制运行。** 原有订阅不修改，新节点作为独立本地配置导入，分流放在全局覆写中。

## 默认分流与 DNS

规则按下面的优先级从上到下匹配：

1. Claude 自家域名走海外：`claude.ai`、`claude.com`、`anthropic.com`、`claudeusercontent.com`、`claudemcpclient.com`。
2. 局域网与保留地址直连，包括 `100.64.0.0/10`。
3. 通过维护中的服务分类实现指定服务直连，并保留 `mirrorakam` 关键词匹配；技能包不枚举具体国内域名。
4. 海外域名分类 `GEOSITE,geolocation-!cn` 走海外，排在国内名单前。
5. 国内域名与国内 IP 名单直连，使用 Loyalsoldier 的 `direct.txt` 和 `cncidr.txt`，每天更新；IP 类规则不为匹配而触发本地解析。
6. 其余流量全部进入手动“海外出口”组，该组没有 DIRECT，也不自动换节点。

TUN 接管后仍按规则分流。国内网站显示国内出口是预期行为；DIRECT 表示交给操作系统路由，不等于固定指定某个 Wi-Fi 或 VPN。

DNS 使用 fake-IP。海外域名经海外出口使用海外 DNS，国内直连域名与节点自身域名按配置使用国内 DNS。关闭核心 IPv6 和 DNS AAAA 返回；公网 IPv6 是否实际被阻断需要单独实测，不能仅凭设置开关宣称通过。

## 断网防护与主动关闭

有两项独立选择：

- 同时关闭“系统代理”和“TUN”，是否解除防护并恢复原网络。
- 退出客户端，是否解除防护并恢复原网络。

默认严格模式不会把节点连接失败当成退出意图。选中节点失效时，海外请求失败，国内直连仍可继续；TUN 故障时则按防护状态限制普通用户的外网请求。

如果选择“退出客户端就恢复原网络”，意外退出同样会放行。网页已经打开不意味着后续请求固定出口；恢复原网络后，网页重连可能使用原网络。

macOS 防护使用 `com.apple/clash-guard` 锚点和 `local.clash-guard` 系统服务，文件位于 `/Library/Application Support/clash-guard/`。规则针对普通用户，root 程序不受同样限制。守护存在系统调度窗口，不承诺任何情况下瞬时零泄漏。

## 验收怎么看

验收以普通用户请求和核心日志为依据，不把 root 的连通性当成防护证据。TUN 测试清理代理环境变量，curl 使用 `-q --noproxy '*'`。

| 项目 | 核验内容 |
| --- | --- |
| 1 | 规则模式、真实 TUN、自启、DNS 的 IPv6 设置 |
| 2 | 规则顺序、兜底出口、手动组不含 DIRECT |
| 3 | 用户提供的目标成功且核心日志 DIRECT，测 IP 接口返回已核实的本地出口 |
| 4 | 海外测试请求的规则、出口和实际 IP |
| 5 | DNS 路径、随机查询日志及外部解析器证据 |
| 6 | 裸 IP 请求由 TUN 接管 |
| 7 | 防护安装阶段无未处理错误 |
| 8 | PF 规则和守护服务实际运行 |
| 9 | 坏节点时海外失败、无直连回退，国内仍可用 |
| 10 | TUN 运行故障时普通用户外网被阻止 |
| 11 | 客户端退出符合所选模式，随后恢复正常 |

指定测试服务不可用时保留缺项；只有你同意具体替代证据，才按替代结果继续。HTTP 403 只证明收到服务端响应，不代表登录或页面功能成功。

实际重启、已打开网页的后台连接、WebSocket、完整 UDP 行为等未执行时均保留“未测”。脚本的成功提示不能替代逐项报告。

## 失败与还原

失败后回到原对话，发送本批次日志路径，让 AI **先读日志和恢复结果**，不要原样重复执行失败的安装脚本。

- **电脑还原：** 使用本批实际备份目录中的 `sudo sh "…/restore.sh"`，离线可用，恢复配置及原网络状态。
- **只解除防护：** `sudo sh "/Library/Application Support/clash-guard/off.sh"`。它不等于完整还原。
- **VPS 还原：** 在本机运行该批次 `restore-node.sh`；SSH 不通时，在厂商控制台运行脚本打印的服务器恢复命令。
- **VPS 诊断：** 运行 `collect-diagnostics.sh`，由 AI 读取下载的诊断报告。

服务器与电脑分阶段提交。节点已经测通并提交、后续电脑配置失败时，只还原电脑，保留可用节点。需要撤销两端时，先还原电脑，再还原 VPS。

自动恢复不能保证外部断网、服务器不可用或系统故障时互联网必然恢复；以日志中的实际状态和急救说明为准。

## 发布内容与验证状态

仓库仅包含通用技能说明、脚本和隔离测试，不包含个人节点配置、真实密码/私钥、订阅令牌、公司域名、实际网络快照或本机备份。

代码保留海外服务及运行端点、通用局域网/保留地址、DNS 地址和隔离测试用假数据。文档不附外部参考网址；国内规则在运行时加载，用户提供的测试目标仅存入本机私有选项。网卡接口、用户名、UID、代理端口和路径在目标机器上发现；测试中的 `utun8`、`501`、`7897` 等不是部署时固定使用的本机参数。新建 VPS 节点的默认端口 `18443` 可配置且必须先检查空闲。

运行后生成的 `node.json`、`plan.json`、`settings.json`、备份和诊断可能含敏感信息，务必留在本机私有目录。`.gitignore` 已覆盖常见生成物；提交额外文件前仍需检查。

本版本完成了 54 项隔离测试、Mihomo 原生配置解析、独立核心 loopback 启动与退出清理检查。真实 Linux 部署、管理员安装与每台新设备的现场验收仍需执行。Xray 原生解析器的开发机验证未完成：官方测试二进制下载超时，未执行不完整文件。

开发测试在 macOS 上运行，需要 Python、Ruby、Node.js，以及允许查看自身测试进程的环境；不执行 sudo 或真实 VPS 部署：

```sh
python3 -B -m unittest discover -s tests -v
```
