# 验收与故障证据

## 测试身份和证据

所有业务探针在普通桌面用户下运行。管理员事务内部用 `sudo -u <实际用户名>` 或等价的身份切换；记录实际 UID，拒绝 UID 0 的业务验收。清除大小写 HTTP/HTTPS/ALL/NO_PROXY 环境，curl 加 `-q`（第一参数）和 `--noproxy '*'`，防止 `.curlrc` 或环境偷偷指定代理。加连接和总超时，不使用 `-k` 掩盖 TLS 问题。

可用本技能 `scripts/probe.py` 做有界 HTTP 探针：

```sh
python3 scripts/probe.py --url "${DOMESTIC_TEST_URL:?请先填写已确认的测试地址}" --output /tmp/proxy-probe.json
```

它拒绝 root、含账号或 query 的 URL，默认不保存响应正文，只在正文是纯 IP 或已识别 IP 字段时输出该地址。退出 0 表示探针报告已生成，不表示所有请求成功；逐项读取 `curl_exit`、`http_status`、`reported_ip`。响应体限制为 64 KiB，`response_limit_reached=true`（curl 63）表示内容超限，不能当作断网。它不跟随重定向，所以 301 仅证明收到重定向。`remote_ip` 可能是 fake-IP 或目标服务器，不能当成本机公网出口。报告本身也不证明 TUN/规则/防火墙。

自动部署前填写 `domestic_tests`：2～4 个不同主机的国内普通网页地址、1 个测 IP 接口、已核实的本地公网 IPv4 及地区确认。字段详见 [automation.md](automation.md)。这些地址只写入本机私有部署选项，不能回填到分发技能包。测 IP 接口须返回纯 IP 或 JSON 的 `ip`、`origin`、`query` 字段；不从任意网页文字中猜测出口。目标不会因用于验收而自动加入直连规则。

开始探针前录制核心连接/DNS 日志，标记批次 ID、开始/结束时间，关联请求域名、源端口、规则、策略链与出口。API 连接轮询可能漏掉短连接，优先核心事件日志；必要时临时启用更详细日志，结束恢复并去除敏感内容。

HTTP 层和业务层分开：403/401 证明有响应，不证明页面/登录可用；200 的 nginx 默认页不证明目标应用正常。浏览器验证必须在用户实际浏览器/实际环境中做，服务器网页抓取与另开自动化浏览器不能替代。

## 11 项报告表

| 项 | 必要证据与通过条件 |
|---|---|
| 1 运行状态 | 核心 rule 模式，TUN 配置与真实接口一致；客户端自启设置存在；DNS AAAA 关闭并实测。未重启系统就把开机流程列为未测。 |
| 2 规则结构 | 最终兜底海外；DIRECT 仅获准类别；海外组是 select、递归无 DIRECT/自动回退；原订阅未改变。 |
| 3 国内 | 用户提供并确认的普通域名请求成功，且核心日志为 DIRECT；用户指定的测 IP 接口也命中 DIRECT，返回地址与部署前核实的本地公网出口一致。技能包不预置具体国内域名或测试网址；未提供目标则停止准备，不能记为通过。 |
| 4 海外 | api.ipify.org、ipinfo.io、claude.ai、statsig.anthropic.com、httpbin.org、googletagmanager.com 逐个记录命中海外；能返回出口 IP 的接口须一致，按当前服务地区要求核验。其他站用规则/链路证据，不能虚称每个站都返回 IP。 |
| 5 DNS | 三个随机子域名的解析证据与海外解析器连接证据；指定 DNS 泄漏服务可用则测试并记录解析器地区。失败时按下述边界处理。 |
| 6 裸 IP | 普通用户对已确认的公网裸 IPv4 发起无显式代理请求，被 TUN 接管，核心日志有海外链路；HTTP 重定向可作连接证据。 |
| 7 安装 | 读取本次防护安装 exit、每个阶段和最终普通用户健康检查；0 错误才通过。 |
| 8 防护加载 | PF 已启用，父/子锚点可达，正确规则已加载，local.clash-guard 运行；自愈与开机分别标明是否实测。 |
| 9 坏节点 | 切到事务内创建的不可达测试节点后，海外请求失败、组不切换且无本地出口回退；用户提供的普通域名仍 DIRECT 可达；恢复原选择并验证。 |
| 10 TUN 停止 | 严格/故障状态下，普通用户新建裸 IP 外网连接被拒绝；检查 PF 计数或抓包，排除只是 DNS 失败；之后恢复并验证。 |
| 11 GUI 退出 | 严格模式等待约 3 秒后测新连接拒绝，包含 root 核心仍监听时的本地代理绕行测试；再重开和验证。若已选退出即恢复，此项改验原网络恢复并明确严格阻断不适用。 |

第 9～11 项必须处于一个本地独立事务中，每项后先恢复健康再进入下一项；任何失败终止后续并恢复原状态。预先记录配置、选择、故障节点/规则增删清单；终态不残留测试节点。核心故障演练与用户主动关闭模式不得混淆。

在第 10/11 项要求保持受限的状态中，要额外尝试明确指定本机 HTTP/SOCKS 入口的请求，证明存活 root 核心不能绕过防护。该附加探针有意使用代理，不混进主 TUN 测试。选择恢复原网络的分支则验证清理和原生访问，不套用受限状态的断言。不要把第三方抓包器/其他 root 中继也未经验证声称覆盖。

## 已打开网页与后台重连

针对“网页已打开，节点断了会怎样”的要求，在第 9～11 项分别区分旧连接、后台自动重试、新连接和缓存显示：

- 节点坏了而 GUI/TUN 和开启意图保持：海外新请求与重连仍应命中固定海外组并失败，不回退 DIRECT；国内继续按获准规则直连。浏览器可能保留缓存内容或显示已缓冲数据，不能凭页面还看得见判断仍在联网。
- TUN/核心异常且策略要求保护：已有连接和新连接都需要证据；只有新建 curl 成功阻断，不代表所有旧 states、连接迁移或 UDP 都已验完。
- 已选择主动关闭/退出后恢复原网络：后台请求可能恢复为本地出口。这是此模式的已知语义，不应记录为严格保护通过。

测试前让用户保存未提交内容，禁止借故障演练自动发送聊天消息、上传文件或提交业务表单。优先用无账号的受控页面产生可识别的无敏感数据请求；必须同时查看真实目标网页时，只读刷新/现有日志，按用户授权范围操作。不同浏览器 profile 或插件代理需各自核对。

将测试页面流量与核心日志、PF 计数或必要抓包关联，记录故障/重试/恢复时间和实际观察窗口。裸 curl 结果、网页缓存截图或单次出口卡片均不能替代后台连接证据。没有条件观察的协议/旧连接列为未测；不为取得“通过”临时关闭防护。

## DNS 泄漏证据的限制

DoH 将查询域名封装在 HTTPS 内。应用直接请求外部 DoH 时，核心普通连接日志可能只显示解析器域名；不能因此宣称看到了随机查询名。若要求“三个随机域名出现在代理日志”，需让它们进入本核心 DNS（其上游为 DoH）并启用相应 DNS 日志，或用解析器侧查询证据，另记录 DoH 连接经海外策略。

指定 DNS 泄漏检测 API 若 NXDOMAIN/停服，保留原测试失败，提出有解析器出口明细的替代方案，经用户接受才记替代通过；不能把国内 DNS 换掉来掩盖服务自身不可用。

“海外 DNS 出口”针对海外解析链路与泄漏检测请求；国内直连域名按需求使用国内 DNS 是有意策略，不等于所有解析器物理上都在海外。应用 DoH、节点远端解析、系统 DNS 各自记录。DNS 出口与业务出口可能不同，不能只看 IP 是否完全一样判定泄漏。

## 常见误判与修正

- 坏节点时指定的直连测试目标也失败：不要先改规则。查看测试是否用 `--resolve` 强绑了海外 DNS 返回 IP，导致失去域名映射而落入 MATCH；国内探针应使用普通域名。故障 PF 测试反而应加真实裸 IP，排除 DNS 假失败。
- curl exit 7/28 可作为拒绝候选结果，需同时排除目标离线和路由故障；exit 6 只说明 DNS 失败，exit 35 是 TLS/握手失败，不能直接归因 PF。
- DNS 缓存旧 fake-IP、服务启动慢、端口换位分别定位，不无限重装服务。
- 用户说安装完成，只能说明脚本提示；读取具体批次日志、时间、终态并复查，不能继承旧批次“通过”。

## 额外边界

按实际需求补测 IPv6、UDP/QUIC、NTP、睡眠唤醒、网络或网卡切换、设备重启和 PF 被外部清理。没做就明确未测。

报告每项含：状态（通过/失败/替代/未测/不适用）、时间、配置版本、普通用户 UID、命令/URL、核心日志证据、出口、限制。结尾附实际路径的完整还原和 `off.sh` 命令，核对桌面急救一致，以及当前客户端、TUN、策略选择、系统代理/DNS、防护模式。
